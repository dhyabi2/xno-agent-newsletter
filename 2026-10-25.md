# 2026-10-25: Two x402 payment stacks now accept Nano (XNO) payments

Window: 2026-10-24 05:20 UTC to 2026-10-25 05:20 UTC, plus two merges found after the issues that should have
carried them. Each item below is a merged pull request on a public repository, checked on its own page.

**portal-tunnel's paid routes can be paid in Nano.** gosuda's portal-tunnel gateway charged for x402 paid routes in
Sui and Casper only. It now also offers `nano:mainnet`. The gateway settles the XNO payment in-process, using the
node endpoints its operator configures. Each block hash can pay only once per gateway. The maintainer approved it
"for the opt-in Nano integration". They also asked that a few limits be tracked at the facilitator boundary before
anyone relies on Nano paid routes in production. The maintainer merged it on 2026-10-24 at 04:57 UTC (commit `a8d2df2` on `main`).
https://github.com/gosuda/portal-tunnel/pull/688

**CoinPayPortal's x402 facilitator verifies Nano payments.** Before this change, the facilitator rejected `nano` as
an unsupported network. Now a merchant can add XNO beside BTC, EVM and Solana. The facilitator checks the Nano address
checksum. It accepts a payment only when a confirmed send block pays the merchant's address at least the price, as
read from a node the operator chooses. A block hash cannot be used twice. The server holds no keys and moves no
funds. The SDK gained an `xno` payment method. The maintainer merged it on 2026-10-13 (commit `80f1996` on `master`);
it was not reported in an issue until now.
https://github.com/profullstack/coinpayportal/pull/429
