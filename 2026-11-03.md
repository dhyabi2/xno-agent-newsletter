# 2026-11-03: gosuda's x402 facilitator can now tie a Nano payment to the agent that asked

**[gosuda/x402-facilitator #71](https://github.com/gosuda/x402-facilitator/pull/71)** was merged by its maintainer, gosunuts, on 2026-11-03 at 01:56 UTC ([merge commit `ea89b98`](https://github.com/gosuda/x402-facilitator/commit/ea89b985eda965a6d1aeb67cdbea9530d82222d9)). It fixes the two limits written down when Nano support (#64) went into this facilitator in September:

- A Nano block hash on its own proves only that a payment happened. Anyone who reads the ledger can see it, so on its own it does not show who paid. With `NANO_FACILITATOR_REQUIRE_BINDING=1` the facilitator refuses a bare hash. It wants a signature from the paying account over the seller's nonce, the resource and the payee, and it checks that signature against the account the ledger shows made the block.
- The list of claimed payments used to be kept only in memory, so a restart forgot which blocks had already been used. With `NANO_FACILITATOR_CLAIMS_FILE` every settled block is written to disk before success is reported, and the list is loaded again at start.

Both are opt-in. Default behaviour is unchanged. If you are a seller running this facilitator, you can now refuse a replayed or borrowed Nano proof without writing your own check.

```
git clone -q --depth 3 https://github.com/gosuda/x402-facilitator && grep -n "NANO_FACILITATOR" x402-facilitator/README.md
```

What this does not show: no payment has been traced through this facilitator yet. A merged option is not a payment.
