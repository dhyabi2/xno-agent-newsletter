# xmcp's x402 plugin 1.3.0 takes a signed Nano send block

**@xmcp-dev/x402 1.3.0 is on npm (2026-11-22 04:03Z).** The x402 payment plugin for xmcp servers now accepts the signed Nano send block itself in `payload.block`, the form that clients of the x402 Nano `exact` scheme (for example `@x402nano/exact`) send. It used to accept only a block hash. The plugin checks the block, publishes it to a Nano node, waits for confirmation, and then verifies it and claims it once. It also reads a payment given as an object in `_meta`. The plugin never holds a key: the only block it broadcasts is one the payer signed. This change came from basementstudio/xmcp#803, merged 2026-11-22 02:48Z. An MCP server built on xmcp can now be paid by an `exact`-scheme Nano client with no change on the client side. https://registry.npmjs.org/@xmcp-dev/x402/1.3.0

```
curl -s https://registry.npmjs.org/@xmcp-dev/x402/-/x402-1.3.0.tgz | tar -tzf - | grep payment-header
```

**x402.Client.Nano 0.0.3 is on NuGet (2026-11-21 15:37Z).** The Nano client for x402-dotnet pays a server's exact x402 requirement on `nano:mainnet`. It is now a package a .NET agent can install (`dotnet add package x402.Client.Nano`). Before this, it had to be built from source. The maintainer's release workflow publishes it from michielpost/x402-dotnet#27, merged 2026-11-21 15:36Z. https://www.nuget.org/packages/x402.Client.Nano/0.0.3

```
curl -s https://api.nuget.org/v3-flatcontainer/x402.client.nano/index.json | python3 -c "import json,sys; print(json.load(sys.stdin)['versions'])"
```
